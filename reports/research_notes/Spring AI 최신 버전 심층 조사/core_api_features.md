## 1. ChatClient fluent API: shape, new methods, streaming, multimodality, prompt templates, ChatOptions portability

### Takeaway
In 2.0.x the `ChatClient` is explicitly positioned as *the* primary user-facing API (with `ChatModel` as the lower-level component); its fluent shape is largely the 1.x shape, but 2.0 adds `EntityParamSpec` reliability switches on `.entity(...)`, message metadata, auto-registered `ToolCallingAdvisor`, `.toolContext(Map)`, and changes `.options(...)` to take a `ChatOptions.Builder` (options are now immutable, builder-only).

### Cited Findings
- [2.0.0] GA blog: "Emphasized `ChatClient` as primary user-facing API; `ChatModel` as lower-level component"; options are created via builders, immutable after instantiation, with "reflection-free merging", defaults defined at options level, and the artificial `.options` segment removed from property keys — [2.0.0 GA blog](https://spring.io/blog/2026/06/12/spring-ai-2-0-0-GA-available-now/)
- [2.0.x docs] Creation: inject auto-configured `ChatClient.Builder` and `.build()`, or `ChatClient.create(chatModel)` / `ChatClient.builder(chatModel).build()` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.x docs] Request spec methods: `prompt()`, `prompt(Prompt)`, `prompt(String)`, `.system(...)`, `.user(...)`, `.messages(...)`, `.options(...)`, `.advisors(...)`, `.tools(...)`, `.toolContext(Map)`, `.templateRenderer(...)`, `.mutate()` (on both `ChatClient` and `ChatClientRequestSpec`) — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.x docs] `call()` returns: `.content()` (String), `.chatResponse()` (ChatResponse incl. token metadata), `.chatClientResponse()` (ChatClientResponse with advisor execution context, e.g., retrieved RAG docs), `.entity(Class)`, `.entity(ParameterizedTypeReference)`, `.entity(StructuredOutputConverter)`, `.responseEntity(Class)` (ChatResponse + typed entity together) — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.x docs] `stream()` returns `Flux<String>` via `.content()`, `Flux<ChatResponse>` via `.chatResponse()`, `Flux<ChatClientResponse>` via `.chatClientResponse()` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.0] NEW `EntityParamSpec` on `.entity(...)`: `.entity(ActorFilms.class, spec -> spec.useProviderStructuredOutput().validateSchema())` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html); listed among the docs' "Key 2.0 Features" with message metadata, `ChatClientBuilderConfigurer`, ToolCallingAdvisor auto-registration, `ChatClientResponse` and `responseEntity` (note: that "Key 2.0 Features" list was produced by the fetch summarizer and may conflate items present since 1.x) — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.x docs] Message metadata: `.user(u -> u.text("...").metadata("messageId","msg-123"))`, `.system(s -> s.text("...").metadata("version","1.0"))`, or `.metadata(Map)` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.0] **Options change:** `ChatClient.options()` / `.defaultOptions()` now accept a `ChatOptions.Builder`, not a built instance — e.g. `.options(AnthropicChatOptions.builder().maxTokens(100).temperature(0.7))`; `ChatModel.call(Prompt)` still requires a built `ChatOptions` — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html). Docs also show a lambda form `.options(opts -> opts.temperature(0.7).topP(0.9))` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.0] Options immutability: `ChatOptions#copy()` and `*Options#fromOptions(...)` removed; use `options.mutate().foo(...).build()`; returned collections are unmodifiable; `ChatModel#getDefaultOptions()` deprecated in favor of `ChatModel#getOptions()`; `N()` renamed `n()` in builders; `ChatOptions` setters removed (builder-only) — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html), [GitHub releases](https://github.com/spring-projects/spring-ai/releases)
- [2.0.0] Property flattening: `spring.ai.openai.embedding.options.model` → `spring.ai.openai.embedding.model` (applies to Embedding, Image, Audio, Moderation, OCR, etc.) — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.0] `.tools(Consumer<ToolSpec>)` / `ChatClient.ToolSpec` removed → `.tools(myCallback).toolContext(Map.of("tenantId","acme"))`; `buildRequestPrompt` removed from public API — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.0] New `ChatClient.builder(chatModel, observationRegistry, chatClientObservationConvention, advisorObservationConvention, ToolCallingAdvisor.Builder)` 5-arg overload; Boot alternative `spring.ai.chat.client.tool-calling.advisor-order=300` or a `ToolCallingAdvisor.Builder<?>` bean — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html). Docs show `ChatClientBuilderConfigurer` + `ObjectProvider<ToolCallingAdvisor.Builder<?>>` for building multiple ChatClients (e.g., OpenAI + Anthropic) while keeping observability — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.x docs] Builder defaults: `defaultSystem`, `defaultUser`, `defaultOptions`, `defaultTools`, `defaultToolContext(Map)`, `defaultAdvisors(...)` / `defaultAdvisors(a -> a.advisors(...).param(k,v))`, `defaultTemplateRenderer(...)`; system params at call time via `.system(sp -> sp.param("voice", voice))` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [2.0.x docs] Templates: default renderer is StringTemplate (`StTemplateRenderer`) with `{var}` syntax; custom delimiters via `StTemplateRenderer.builder().startDelimiterToken('<').endDelimiterToken('>').build()`; `new NoOpTemplateRenderer()` disables templating; `PromptTemplate.builder().renderer(...).template(...).variables(...)` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html), [RAG docs](https://docs.spring.io/spring-ai/reference/api/retrieval-augmented-generation.html)
- [2.0.x docs] Multimodal input: `.user(u -> u.text("Explain...").media(MimeTypeUtils.IMAGE_PNG, new ClassPathResource("/multimodal.test.png")))`, or `UserMessage.builder().text(...).media(new Media(MimeTypeUtils.IMAGE_PNG, resource)).build()`; media applies only to `UserMessage` — system and assistant messages are text-only — [Multimodality docs](https://docs.spring.io/spring-ai/reference/api/multimodality.html)
- [2.0.1] `Media.Builder.data(Object)` removed; typed overloads `data(byte[])`, `data(String)`, `data(URI)`, `data(URL)`, `data(Resource)` — listed as a 2.0.1 breaking change in the [2.0.1 blog](https://spring.io/blog/2026/08/21/spring-ai-2-0-1-available-now/) (the upgrade-notes extract placed it in the 2.0.0 body — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html))
- [2.0.x docs] Chat model capability matrix (as rendered): Anthropic text/pdf/image; Google GenAI text/pdf/image/audio/video; Mistral text/image/audio; OpenAI text/image/audio (in/out); Ollama text/image; Bedrock Converse text/image/video/docs (pdf, html, md, docx); DeepSeek text; plus OpenAI-proxy rows Groq, NVIDIA, Perplexity and MiniMax (Anthropic-proxy) — [Chat comparison](https://docs.spring.io/spring-ai/reference/api/chat/comparison.html)
- [2.0.0] Supported first-party chat providers consolidated to seven: OpenAI (SDK variant), Anthropic (SDK variant), Amazon Bedrock, Google GenAI, Mistral AI, DeepSeek, Ollama; OCI GenAI (Oracle) and Azure Cosmos DB (Microsoft) are vendor-maintained — [2.0.0 GA blog](https://spring.io/blog/2026/06/12/spring-ai-2-0-0-GA-available-now/). Removed modules: `spring-ai-azure-openai`, `spring-ai-openai-sdk` (both → `spring-ai-openai`), `spring-ai-hanadb-store`; MiniMax support removed (use Anthropic module with `https://api.minimax.io/anthropic`) — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.0] Foundation: Spring Boot 4.0/4.1 + Spring Framework 7.0 baseline; Jackson 2 → Jackson 3 with new `JsonHelper` class; codebase fully annotated with JSpecify null-safety annotations (Kotlin-idiomatic APIs) — [2.0.0 GA blog](https://spring.io/blog/2026/06/12/spring-ai-2-0-0-GA-available-now/). 2.0.0-M1 was built on Boot 4.0 / Framework 7.0 with a Jakarta EE 11 baseline — [2.0.0-M1 blog (search snippet)](https://spring.io/blog/2025/12/11/spring-ai-2-0-0-M1-available-now/)
- [2.1.0-M1 MILESTONE] Messages move to an ordered list of `MessagePart`s (`TextPart`, `ReasoningPart`, `ToolCallPart`, `ToolResultPart`, `MediaPart`, `UnknownPart`): `UserMessage.builder().part(TextPart.of("...")).part(MediaPart.of(chart)).build()`; `answer.getReasoning()` returns `ReasoningPart`s — [2.1.0-M1 blog](https://spring.io/blog/2026/09/25/spring-ai-2-1-0-M1-available-now/)

### Inferences
- The `.options(Builder)` change is the most visible source-level break for ChatClient users; portable code can pass `ChatOptions.builder()` while provider-specific code passes e.g. `AnthropicChatOptions.builder()` — the merge happens reflection-free inside ChatClient.
- Because 2.0.1 `Media` is `UserMessage`-only, the 2.1 `MessagePart` model is the first step toward multimodal/structured assistant output in the portable API.

### Gaps
- Could not confirm whether `responseEntity(...)` and message metadata debuted in 2.0 or already existed in 1.1 (fetch-summarizer labeling only).
- No source fetched on video/audio input through `ChatClient` specifically beyond provider matrix rows.

## 2. Advisors API: built-ins, ordering, recursive advisors — what's new

### Takeaway
The advisor interfaces (`CallAdvisor`, `StreamAdvisor`, `BaseAdvisor`, chains, `ChatClientRequest/Response`) are unchanged from 1.0/1.1; recursive advisors debuted in 1.1, but 2.0 makes the advisor chain the home of the tool loop (`ToolCallingAdvisor`, auto-registered at `HIGHEST_PRECEDENCE + 300`), moves memory advisors to `+200` (outside the loop), adds `ToolAdvisor`/`MemoryAdvisor` marker interfaces, `ToolSearchToolCallingAdvisor`, and removes `PromptChatMemoryAdvisor`.

### Cited Findings
- [2.0.x docs] Core contracts: `Advisor extends Ordered { String getName(); }`; `CallAdvisor.adviseCall(ChatClientRequest, CallAdvisorChain)`; `StreamAdvisor.adviseStream(ChatClientRequest, StreamAdvisorChain)`; `CallAdvisorChain.nextCall(...)`, `getCallAdvisors()`; `StreamAdvisorChain.nextStream(...)`, `getStreamAdvisors()`; shared `advise-context` map; `BaseAdvisor` with `before(...)`/`after(...)` — [Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors.html)
- [2.0.x docs] Ordering: lower `getOrder()` executes first on request and last on response; streaming aggregation via `ChatClientMessageAggregator().aggregateChatClientResponse(...)` — [Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors.html)
- [2.0.x docs] Built-in advisors: `MessageChatMemoryAdvisor`, `VectorStoreChatMemoryAdvisor` (memory into system text), `QuestionAnswerAdvisor` (naive RAG), `RetrievalAugmentationAdvisor` (modular RAG, `org.springframework.ai.rag`), `ReReadingAdvisor` (RE2 example), `ToolCallingAdvisor`, `SafeGuardAdvisor` (content safety), `SimpleLoggerAdvisor` — [Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors.html); `StructuredOutputValidationAdvisor` and `ToolSearchToolCallingAdvisor` are documented as recursive / tool advisors — [Recursive Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors-recursive.html), [Tool Search docs](https://docs.spring.io/spring-ai/reference/api/tools/tool-search-tool.html)
- [2.0.x docs] `SimpleLoggerAdvisor` logs at DEBUG (`logging.level.org.springframework.ai.chat.client.advisor=DEBUG`); custom formatters via `new SimpleLoggerAdvisor(requestToString, responseToString, order)` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html)
- [1.1] Recursive advisors debuted in 1.1 ("self-improving agents", "LLM-as-a-Judge", built-in implementations with configurable observations) — [1.1 GA blog](https://spring.io/blog/2025/11/12/spring-ai-1-1-GA-released/)
- [2.0.x docs] Recursion mechanism: `callAdvisorChain.copy(this)` creates a sub-chain of only the advisors *after* the current one so a recursive advisor can loop without re-running preceding advisors; built-in recursive advisors: `ToolCallingAdvisor` and `StructuredOutputValidationAdvisor`; custom recursive advisors should use `UsageAccumulator` (`addRoundResponse`, `applyAccumulatedUsage`) backed by `org.springframework.ai.support.UsageCalculator` — [Recursive Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors-recursive.html)
- [2.0.0] `ToolCallingAdvisor` builder: `toolCallingManager(...)`, `advisorOrder(int)` (default `BaseAdvisor.HIGHEST_PRECEDENCE + 300`), `toolExecutionEligibilityChecker(...)`, `disableInternalConversationHistory()` / `conversationHistoryEnabled(boolean)` — [Recursive Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors-recursive.html). Renamed from `ToolCallAdvisor` — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.0] `Advisor.DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER` changed `HIGHEST_PRECEDENCE + 1000` → `HIGHEST_PRECEDENCE + 200`, so memory advisors run outside the `ToolCallingAdvisor` (+300) by default — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html); "where an advisor sits relative to ToolCallingAdvisor determines whether it sees only the final result (outside) or every iteration (inside)" — [Composable tool calling blog](https://spring.io/blog/2026/06/15/spring-ai-composable-tool-calling/)
- [2.0.0] New marker interfaces: `ToolAdvisor` (custom advisors owning the tool loop; prevents duplicate auto-registration; "exactly one ToolAdvisor may be present") and `MemoryAdvisor` (extended by `BaseChatMemoryAdvisor`; `DefaultChatClient` uses it to detect downstream memory advisors and disable ToolCallingAdvisor's internal history) — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html), [Composable tool calling blog](https://spring.io/blog/2026/06/15/spring-ai-composable-tool-calling/)
- [2.0.0] `ToolCallingAdvisor` lifecycle hooks for subclasses: `doInitializeLoop`/`doInitializeLoopStream`, `doBeforeCall`/`doBeforeStream`, `doAfterCall`/`doAfterStream`, `doFinalizeLoop`/`doFinalizeLoopStream`; register a `ToolCallingAdvisor.Builder<?>` bean in an auto-config ordered before `ChatClientAutoConfiguration` — [Composable tool calling blog](https://spring.io/blog/2026/06/15/spring-ai-composable-tool-calling/)
- [2.0.0] GA blog: tool loops are "first-class, composable components within the advisor chain, supporting looping and mid-stream re-entry" — [2.0.0 GA blog](https://spring.io/blog/2026/06/12/spring-ai-2-0-0-GA-available-now/)
- [2.0.0] `PromptChatMemoryAdvisor` removed (use `MessageChatMemoryAdvisor`); module `spring-ai-advisors-vector-store` renamed `spring-ai-vector-store-advisor` — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.0] Per-call advisor params: `AdvisorParams.toolCallingAdvisorAutoRegister(false)` and `AdvisorParams.ENABLE_NATIVE_STRUCTURED_OUTPUT` — [ChatClient docs](https://docs.spring.io/spring-ai/reference/api/chatclient.html), [Native structured output docs](https://docs.spring.io/spring-ai/reference/api/structured-output/native.html)

### Inferences
- Any custom advisor that must observe each tool round (e.g., auditing, guardrails on tool results) should be ordered > +300; anything that should see only the user turn/final answer (memory, logging of final output) should be < +300.
- Upgrading custom memory advisors that relied on the old +1000 order will silently change behavior (they would now be inside the loop if left at +1000).

### Gaps
- `SafeGuardAdvisor` configuration details (sensitive words, failure response) were not captured in 2.0.1 docs fetch.
- Whether `RetrievalAugmentationAdvisor` still carries the "experimental" label it had in 1.x is not verified (the fetch summarizer's "Stable" table is not a doc fact).

## 3. Tool calling: @Tool/@ToolParam, ToolCallback, ToolCallingManager, tool context, return-direct, user-controlled execution, dynamic resolution — changes

### Takeaway
2.0.0 is the biggest tool-calling change since 1.0: the per-`ChatModel` internal tool loop is removed; `ChatClient` auto-registers a single `ToolCallingAdvisor`; `SpringBeanToolCallbackResolver`/`toolNames()` and `internalToolExecutionEnabled` are gone; resolution fallback is off by default; and 2.0.1 adds per-turn tool-call limits and cumulative usage across the loop.

### Cited Findings
- [2.0.0] `ChatModel.call(prompt)` / `ChatModel.stream(prompt)` now return raw responses without automatic tool execution; use `ChatClient` (auto `ToolCallingAdvisor`) or drive `ToolCallingManager` manually — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html). In 1.x "each chat model implementation contained its own private tool execution loop" — [Composable tool calling blog](https://spring.io/blog/2026/06/15/spring-ai-composable-tool-calling/)
- [2.0.x docs] `@Tool` attributes: `name`, `description`, `returnDirect`, `resultConverter` (`ToolCallResultConverter`); `@ToolParam` attributes: `description`, `required` (default `true`) — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html)
- [2.0.x docs] `ToolCallback` = `getToolDefinition()`, `getToolMetadata()`, `call(String)`, `call(String, ToolContext)`; `ToolDefinition` = `name()`, `description()`, `inputSchema()` (built via `ToolDefinition.builder()` or `ToolDefinitions.builder(method)`); `ToolMetadata.builder().returnDirect(true)` — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html)
- [2.0.x docs] Programmatic: `MethodToolCallback.builder().toolDefinition(...).toolMethod(method).toolObject(obj).build()`; `FunctionToolCallback.builder("currentWeather", weatherService::getWeather).description(...).inputType(WeatherRequest.class).build()` (Function/Supplier/Consumer/BiFunction); `ToolCallbacks.from(new MyTools())` — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html)
- [2.0.0] Removed `SpringBeanToolCallbackResolver` and `toolNames(...)`: bare `@Bean Function<...>` + `@Description` no longer resolves by name; declare `@Bean ToolCallback` (e.g. `FunctionToolCallback`) or use `@Tool` objects — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html). Legacy `FunctionCallback`/`FunctionCallingOptions`/`defaultFunctions`/`.functions()` → `ToolCallback`/`ToolCallingChatOptions`/`defaultTools`/`.tools()` — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.x docs] `ToolContext`: tool methods accept a `ToolContext` param; pass via `.toolContext(Map.of("tenantId","acme"))` (not exposed to the model) — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html)
- [2.0.x docs] `returnDirect` is honored only if **all** tools called in a round have `returnDirect = true`; `ToolCallingAdvisor` breaks the loop in that case — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html), [Recursive Advisors docs](https://docs.spring.io/spring-ai/reference/api/advisors-recursive.html)
- [2.0.0] Auto-registration: `DefaultChatClient` auto-registers exactly one `ToolCallingAdvisor` (registering a second fails with an explicit error per Tools docs); disable per call with `AdvisorParams.toolCallingAdvisorAutoRegister(false)` or globally `spring.ai.chat.client.tool-calling.enabled=false`; Upgrade Notes instead say explicit registrations from 1.x "will result in duplicates" (sources differ: error vs. duplicate) — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html), [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.0] User-controlled execution: opt out of auto-registration, then loop `while (response.chatResponse().hasToolCalls()) { ToolExecutionResult r = toolCallingManager.executeToolCalls(prompt, response.chatResponse()); prompt = new Prompt(r.conversationHistory(), chatOptions); ... }` — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html)
- [2.0.0] Removed: `ToolCallingChatOptions.internalToolExecutionEnabled(...)`, `spring.ai.<provider>.chat.internal-tool-execution-enabled`, `ToolExecutionEligibilityPredicate` (→ `ToolExecutionEligibilityChecker`, a `Function<ChatResponse,Boolean>`), `streamToolCallResponses` (it corrupted memory history) — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html), [v2.0.0 release notes](https://github.com/spring-projects/spring-ai/releases/tag/v2.0.0)
- [2.0.0] Dynamic resolution: `ToolCallbackResolver.resolve(String)`; default `StaticToolCallbackResolver` built from all `ToolCallback` beans (MCP providers excluded); **resolution fallback disabled by default** — only tools attached to the request execute; re-enable with `spring.ai.tools.resolution.fallback.enabled=true` or `ToolCallingManager.builder().resolutionFallbackEnabled(true)` ("enable only when you control which tools the resolver exposes") — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html), [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.x docs] Exceptions: `ToolExecutionExceptionProcessor.process(ToolExecutionException)`; default sends `RuntimeException` messages back to the model, rethrows checked exceptions and `Error`s; `spring.ai.tools.throw-exception-on-error` (default `false`) — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html)
- [2.0.1] Tool-call limits in `DefaultToolCallingManager`: `DEFAULT_MAX_CALLS_PER_TOOL = 40`, `DEFAULT_MAX_TOTAL_TOOL_CALLS = 150`; builder `maxCallsPerTool(40)`, `maxCallsPerTool("search",10)`, `excludeToolFromLimit(...)`, `maxTotalToolCalls(150)`, `unlimitedCallsPerTool()`, `onLimitExceeded(ToolCallLimitBehavior.THROW | RETURN_ERROR_RESPONSE)`; counts scoped to the current turn; raises `ToolCallLimitExceededException` — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html), [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html), [2.0.1 blog](https://spring.io/blog/2026/08/21/spring-ai-2-0-1-available-now/)
- [2.0.1] **CONFLICT on property names:** Tools docs list `spring.ai.tools.limits.max-calls-per-tool-default`, `spring.ai.tools.limits.max-calls-per-tool.<name>`, `spring.ai.tools.limits.excluded-tools`, `spring.ai.tools.limits.max-total-tool-calls`, `spring.ai.tools.limits.on-limit-exceeded` — [Tools docs](https://docs.spring.io/spring-ai/reference/api/tools.html); Upgrade Notes show `spring.ai.tools.limits.max-calls-per-tool=40` — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html)
- [2.0.1] `ToolCallingAdvisor` now accumulates token `Usage` across all internal model calls of the loop (previously only the last call's usage) — [Upgrade Notes](https://docs.spring.io/spring-ai/reference/upgrade-notes.html), [2.0.1 blog](https://spring.io/blog/2026/08/21/spring-ai-2-0-1-available-now/)

## 4. Structured output: BeanOutputConverter, entity(), native structured output / JSON schema support per provider
